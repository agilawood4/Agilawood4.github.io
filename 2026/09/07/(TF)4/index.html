Decoder-only Transformer

本章我们重点介绍以 Decoder-only Transformer 为基础的 LLM 核心算法：

现代 Qwen、Llama 等架构都属于 Decoder-only Causal LM，其实现中普遍使用 RoPE、RMSNorm、门控 MLP，并可配置 MHA/GQA

Decoder-only 架构

原始的 Transformer 架构同时包含 Encoder（编码器）和 Decoder（解码器），但现代的很多生成式 LLM（包括 GPT、Llama、Qwen 等），主要采用 Decoder-only Transformer，也就是只保留一系列 Decoder Block

整体数据流为：

这类模型的根本任务是：

P(xt+1∣x1,x2,…,xt)P(x_{t+1}\mid x_1,x_2,\dots,x_t) P(xt+1​∣x1​,x2​,…,xt​)

也就是根据前面模型已经输出的 Token 序列，去预测下一个 Token，这就是所谓的自回归语言建模（Caisal Language Modeling）

Causal LM 的核心约束在于：当前位置 Token 的预测只能用到左侧已有 Token 序列，不能提前看到未来的 Token

Token Embedding

Tokenizer 输出 input_ids 形状为 [B,L][B,L][B,L]，其中 BBB 表示 Batch Size，而 LLL 表示 Sequence Length

换言之，此时序列的每个位置上都是一个整数，而神经网络需要每个位置是一个特征向量，因此首先需要做词元嵌入（Token Embedding）

Embedding Matrix

假设词表大小（Vocabulary Size）为 VVV，神经网络需要的隐层向量维度（Hidden Size）为 HHH，则 Embedding 矩阵为：

E∈RV×HE\in\mathbb R^{V\times H} E∈RV×H

原始输入的 input_ids 形状为：

[B,L][B,L] [B,L]

经过 Embedding 向量化后变成：

[B,L,H][B,L,H] [B,L,H]

经过 Embedding，每个 Token 就从一个整数编号，变成了一个 HHH 维的向量

Hidden State

Hidden State 即隐藏状态，Transformer 处理的常见格式为 [B,L,H][B,L,H][B,L,H]，其表示每个 Batch 中有 BBB 个序列，每个序列长包含 LLL 个 Token，每个 Token 用 HHH 维向量表示

这里每个 HHH 维向量，就是 Token 在神经网络中的隐藏表示，后续每个 Token 的内容经过网络层处理不断融合上下文信息，改变的也是这个 HHH 维向量每个位置上的数值

Query、Key、Value

在 Self-Attention 中，每个 Token 都会产生三个向量

  1. Query
  2. Key
  3. Value

也就是我们经常所说的 Q,K,VQ,K,VQ,K,V 向量

它们都来自同一个输入的 Hidden State，也就是 X∈RB×L×HX\in\mathbb R^{B\times L\times H}X∈RB×L×H，通过三个不同的 Linear 线性层：

Q=XWQK=XWKV=XWVQ = XW_Q\\K = XW_K\\V = XW_V Q=XWQ​K=XWK​V=XWV​

Q、K、V 含义

Q、K、V 的含义如下：

  1. Query：由当前 Token 发出查询
  2. Key：由每一个 Token 提供自己和发出查询那个 Token 的匹配程度
  3. Value：由每一个 Token 提供，如果它和发出查询那个 Token 匹配，应该提供什么信息

因此，Query 会和所有 Key 进行比较，计算 Attention Score，据此决定当前 Token 更关注哪些 Token 的信息，从而对对应的 Value 做加权求和

Attention Score

先不考虑多头注意力的情况，上一步我们得到了：

Q,K,V∈RB×L×HQ,K,V\in\mathbb R^{B\times L\times H} Q,K,V∈RB×L×H

计算：

QK⊤QK^\top QK⊤

其中，Q∈[B,L,H]Q\in[B,L,H]Q∈[B,L,H]，而 K⊤∈[B,H,L]K^\top\in[B,H,L]K⊤∈[B,H,L]，因此 AK⊤∈[B,L,L]AK^\top\in[B,L,L]AK⊤∈[B,L,L]，它表示每个 Token 和其他所有 Token 的相关性

对于每个 Batch 而言，都形成了一个 L×LL\times LL×L 的注意力分数矩阵（Attention Score Matrix）

Causal Mask

目前的注意力机制还存在一个严重问题，如果仅按照上面的步骤做 Self-Attention，每个 Token 都能提取序列中所有 Token 的信息，那么相当于未来信息泄露

对于目标序列 A B C D，模型在预测 B 的时候，甚至已经看到了 C D 的信息

Decoder-only LLM 必须要能满足每个位置在做预测时，只能看到序列中不超过它所在位置的信息，也就是需要加入因果掩码（Causal Mask）

Causal Mask 矩阵

假设序列长度 L=4L=4L=4，则设计 Mask 矩阵：

[0−∞−∞−∞00−∞−∞000−∞0000]\begin{bmatrix} 0 & -\infty & -\infty & -\infty\\ 0 & 0 & -\infty & -\infty\\ 0 & 0 & 0 & -\infty\\ 0 & 0 & 0 & 0\\ \end{bmatrix} ⎣⎢⎢⎢⎡​0000​−∞000​−∞−∞00​−∞−∞−∞0​⎦⎥⎥⎥⎤​

加入到 Attention Score 中：

Smasked=QK⊤d+MS_{\text{masked}} = \frac{QK^\top}{\sqrt d} + M Smasked​=d​QK⊤​+M

然后再做 Softmax

此时因为 e−∞=0e^{-\infty}=0e−∞=0，所以未来位置的 Attention Weight 都会被置 0，后续乘以 VVV 矩阵时也就不会提取这些位置的信息了

GQA

现代 LLM 中还经常看到 GQA（Grouped Query Attention），即分组查询注意力

在标准 MHA 中，Q,K,VQ,K,VQ,K,V 的数量是相同的，即每个 Head 都用自己的 QQQ 去匹配自己的 K,VK,VK,V

而 GQA 支持多个 Query Head 共用一组 K/V Head，比如：

而 GQA 如果进一步减少 K/V Head 数量为 1，变成多个 Query Head 都查询一组 K/V Head，则变成 MQA（Multi-Query Attention）

HuggingFace 当前 Llama 配置中也明确使用 num_key_value_heads 区分这三种情况：

  1. hQ=hK=hV>1h_Q = h_K = h_V > 1hQ​=hK​=hV​>1：GQA（分组查询注意力）
  2. hQ>hK=hV=1h_Q > h_K = h_V = 1hQ​>hK​=hV​=1：MQA（多查询注意力）
  3. hQ>hK=hV=1h_Q > h_K = h_V = 1hQ​>hK​=hV​=1：MHA（标准多头注意力）

Residual Connection

Attention 处理后得到 attention_output，其形状回到 [B,L,H][B,L,H][B,L,H]，Transformer 不会直接使用 attention_output，而是：

x′=x+Attention(x)x^{'} = x + \text{Attention}(x) x′=x+Attention(x)

这就是所谓的残差连接（Residual Connection）

残差连接可以确保，新模块学习在在原特征的基础上新增什么特征，而不是每一层完全重新生成表示

Train vs. Predict

训练阶段和推理阶段需要形成对比

在推理阶段，模型自回归逐个 Token 生成，比如某一条输入是 [w1,w2,w3]，则对应输出的 logits 形状为 [3,vocab_size]

模型对于每个位置都会输出一个 logits 向量，但只有最后一个位置的 logits 被用于预测下一个 Token，也就是只用 w3 对应的 logits 去预测 w4

在训练阶段，输入是整个序列，模型一次性并行计算出所有位置的 logits，比如某一条输入是 [w1,w2,w3,w4]，则对应输出的 logits 形状为 [4,vocab_size]

此时，每个位置对应的 logits 都会和标签做交叉熵损失

位置 logits（模型输出） 训练目标（标签）
1 基于 [w1] 的表征 w2
2 基于 [w1, w2] 的表征 w3
3 基于 [w1, w2, w3] 的表征 w4

训练时，我们的目标是让模型学会在每个位置都能正确预测下一个 Token，因此每个位置的 logits 都要参与损失计算；而推理时，我们的目标是使用已知 Token 序列预测未知 Token，因此只用最后一个位置的 logits 即可（前面的 logits 预测的下一个 Token 本来就是已知的，没有意义）

KV Cache

如果每生成一个新 Token，都重新计算已有 Token 之间的 Attention Score，这无疑会做大量重复的计算

所以推理的时候，我们使用 Key-Value 缓存（KV Cache）

假设我们已经处理了序列 [A,B,C,D] 中所有历史 Token 对应的 K,VK,VK,V 向量，将其保存到 K-cache 和 V-cache 中

在生成新 Token E 时，只需要计算 E 自己的 QE,KE,VEQ_E,K_E,V_EQE​,KE​,VE​，然后把 QEQ_EQE​ 和 KEK_EKE​ 以及历史 K-cache 中的 KKK 计算 Attention 即可，不需要重新计算 A,B,C,D 的 K,VK,VK,V 向量
