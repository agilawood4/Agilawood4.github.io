Hugging Face 预训练模型工作流

本章主要解决如下的问题：

整个工作流可以拆分成如下七个问题来回答：

  1. Hugging Face、Transformers、Datasets、Accelerate、PEFT、TRL 分别负责什么
  2. from_pretrained() 到底加载了什么
  3. AutoConfig、AutoTokenizer、AutoModel 分别是什么
  4. AutoModel 和 AutoModelForCausalLM 有什么区别
  5. config.json 和 model.safetensors 分别是什么
  6. from_config() 和 from_pretrained() 有什么区别
  7. 模型下载到哪里、如何把模型保存到本地、如何从本地加载模型

Hugging Face 生态

Hugging Face 并不是一个简单的 Python 库或者包，它是一套生态，其中各个组件之间的关系如下：

Hugging Face Hub

Hub 可以理解成是面向机器学习模型和数据的 Github

比如 Qwen/Qwen3-0.6B、google-bert/bert-base-uncased、Qwen/Qwen3-8B，它们表示 Repository ID / 仓库 ID，通常的形式为：

Hub 中的模型、数据集本质上都存放在版本控制仓库中，并针对 safetensors、Parquet 等大型机器学习文件做了专门支持

huggingface_hub

huggingface_hub 是用户程序与 Hub 进行通信的 Python SDK

例如我们想从 Hugging Face 上下载一个文件：

它负责从 Hugging Face Hub 指定的仓库中下载我们想要的文件，并且返回文件在本地的路径

实际使用 Transformers 时，很多 Hub 的下载操作都会被 from_pretrained() 自动封装，所以我们平时并不会频繁调用 hf_hub_download()

Hub 下载文件会被缓存在本地，以后再次使用相同版本的文件时，就可以复用缓存

Transformers

Transformers 是 Hugging Face 的一个开源库，可以让我们用几行代码加载、部署、微调目前最先进的预训练模型（BERT、GPT、LLaMA、Qwen 等），不再需要自己从头写模型结构

这是我们后面使用最多的库：

Tokenizers

Tokenizers 是 Hugging Face 开发的一个把文本切成模型能理解的数字 ID 的高性能库，它是 Transformers 的底层依赖，负责把字符串变成 token ID 序列（注意是 Token ID 而不是 Embedding 向量）：

例如：

通常我们不会直接操作底层的 tokenizers 包，而是通过 AutoTokenizer 使用封装好的版本

Datasets

Datasets 是 Hugging Face 开源的数据处理库，帮助我们用统一的 API 加载、处理、缓存各种格式的数据集（json/ csv / Hugging Face Hub 数据集 / Parquet 等），且能够高效处理超大规模数据而不爆内存

例如：

Accelerate

上一章我们已经了解过，Accelerate 主要负责对多 GPU 并行、Mixed Precision、Gradient Accumulation、FSDP / DeepSpeed 进行封装

PEFT

PEFT（Parameter-Efficient Fine-Tuning），即参数高效微调，其目标定位为使用少量新增或选定参数适配大型预训练模型，避免全参数微调的高计算和存储成本

TRL

TRL（Transformers Reinforcement Learning），即 LLM 后训练库，专门做后训练（post-training / 对齐训练），支持 SFT、DPO 等常见后训练策略
