MoE 基本思想

MoE（Mixture of Experts），即混合专家模型，是一种条件计算神经网络架构：模型内部包含多个相互独立的专家网络，对于一个输入，模型根据该输入决定使用哪些专家，再将这些专家的输出组合成最终结果

MoE 的一般数学形式为：

y=∑i=1Ngi(x)Ei(x)\mathbf{y} = \sum_{i=1}^N g_i(\mathbf{x})E_i(\mathbf{x}) y=i=1∑N​gi​(x)Ei​(x)

其中，x\mathbf{x}x 为输入向量，NNN 为专家总数，E(⋅)E(\cdot)E(⋅) 为第 iii 个专家网络，gi(x)g_i(\mathbf{x})gi​(x) 为输入 x\mathbf{x}x 对专家 iii 的使用权重，y\mathbf{y}y 为输出向量

这里我们约定，在现代 Transformer 架构中的 MoE 中，输入 x\mathbf{x}x 和输出 y\mathbf{y}y 对应一个 Token 在中间层的隐藏表示，也就是一个 dmodeld_{model}dmodel​ 维度的向量

上述公式中有两个核心概念需要解释

专家：每个专家 EiE_iEi​ 都是一个具有独立参数的子网络：

Ei(x;θi)E_i(\mathbf{x};\theta_i) Ei​(x;θi​)

不同专家的参数通常不同，所以同一个输入经过不同的专家后，一般会得到不同的输出结果

目前我们把每个专家都理解为不同参数的网络层即可，先不讨论它内部的具体计算

混合：模型不是固定使用某一个专家，而是根据权重 gi(x)g_i(\mathbf{x})gi​(x)，对多个专家的输出进行组合：

y=g1(x)E1(x)+⋯+gN(x)EN(x)\mathbf{y} = g_1(\mathbf{x})E_1(\mathbf{x}) + \dots + g_N(\mathbf{x})E_N(\mathbf{x}) y=g1​(x)E1​(x)+⋯+gN​(x)EN​(x)

通常权重都满足：

gi(x)≥0,∑i=1Ngi(x)=1g_i(\mathbf{x})\ge 0,\quad\sum_{i=1}^N g_i(\mathbf{x}) = 1 gi​(x)≥0,i=1∑N​gi​(x)=1

针对不同输入，MoE 会使用不同的专家组合，这也是 MoE 与普通固定网络最根本的区别之一

为什么需要 MoE

普通稠密网络

普通神经网络可以表示为：

y=F(x,θ)\mathbf{y} = F(\mathbf{x},\theta) y=F(x,θ)

其中 θ\thetaθ 是模型参数

对于不同输入：

x1,x2,… .xT\mathbf{x}_1,\mathbf{x}_2,\dots.\mathbf{x}_T x1​,x2​,….xT​

它们都经过同一个函数：

xt→F(xt;θ)\mathbf{x}_t\to F(\mathbf{x}_t;\theta) xt​→F(xt​;θ)

并且满足，每一个输入向量都会使用同一个网络中的相同参数计算输出，这种方式就称为稠密计算

稠密模型的问题

稠密模型存在扩展规模的问题，如果我们希望模型能力能强，最直观的办法就是已增加模型参数

而参数量的增加，势必会造成单个输入的计算量随之增加，也就是形成如下的核心矛盾：

  • 模型希望拥有更多参数，保存更丰富的知识和变换能力
  • 同时我们又不希望模型处理每条输入时都调用全部的参数

MoE 就是为解决这一核心矛盾而设计的

MoE 核心思想

MoE 的核心思想就在于：把参数拆分成多个可选择的专家

MoE 不再使用一个大网络 F(x)F(\mathbf{x})F(x)，而是准备多个专家：

E1(x),E2(x),…,EN(x)E_1(\mathbf{x}),E_2(\mathbf{x}),\dots,E_N(\mathbf{x}) E1​(x),E2​(x),…,EN​(x)

如果每个专家有 PEP_EPE​ 个参数，那么所有专家的参数总量为：

Pexperts=NPEP_{\text{experts}} = NP_E Pexperts​=NPE​

如果一个输入必须经过全部专家，那么随着专家数 NNN 的增加，模型中参数量还是随之增加，这相当于只是把普通稠密网络换成了多个并行网络：

参数量增加 N 倍⇒计算量增加 N 倍\text{参数量增加 N 倍}\Rightarrow\text{计算量增加 N 倍} 参数量增加 N 倍⇒计算量增加 N 倍

所以 MoE 真正关心的问题不是拥有多个专家，而是要想办法实现：

每个输入只使用其中一部分专家\text{每个输入只使用其中一部分专家} 每个输入只使用其中一部分专家

稀疏 vs. 稠密 MoE

稠密 MoE

经典的 MoE 表达式为：

y=∑i=1Ngi(x)Ei(x)\mathbf{y} = \sum_{i=1}^N g_i(\mathbf{x})E_i(\mathbf{x}) y=i=1∑N​gi​(x)Ei​(x)

如果所有专家权重都非零：

gi(x)>0,i=1,…,Ng_i(\mathbf{x})>0,\quad i=1,\dots,N gi​(x)>0,i=1,…,N

那么为了得到最终输出，必须计算全部专家的输出：

Ei(x),i=1,…,NE_i(\mathbf{x}),\quad i=1,\dots,N Ei​(x),i=1,…,N

这种形式就称为稠密 MoE

稠密 MoE 并没有真正减少专家的计算量，但已经具备了根据输入动态组合专家的能力

稀疏 MoE

当代大模型中的 MoE 则主要采用稀疏激活的实现方式

对于输入 x\mathbf{x}x，只选择 kkk 个专家，定义被选中的专家集合为：

S(x)⊆{1,2,…,N}\mathcal{S}(x) \subseteq\{1,2,\dots,N\} S(x)⊆{1,2,…,N}

集合大小为：

∣S(x)∣=k,k≪N|\mathcal{S}(\mathbf{x})| = k,\quad k\ll N ∣S(x)∣=k,k≪N

此时 MoE 的输出可以写成：

y=∑i∈S(x)gi(x)Ei(x)\mathbf{y} = \sum_{i\in\mathcal{S}(\mathbf{x})}g_i(\mathbf{x})E_i(\mathbf{x}) y=i∈S(x)∑​gi​(x)Ei​(x)

对于没有选择的专家 i∉S(x)i\notin\mathcal{S}(\mathbf{x})i∈/​S(x)，可以认为其权重为零，即 gi(x)=0g_i(\mathbf{x})=0gi​(x)=0，因此这些专家不需要执行对当前输入的计算

二者对比

相比于稠密 MoE，稀疏 MoE 的关键不是权重小，而是未选择的专家不行计算，换言之，二者的区别在于：是否真正跳过了对于未选择专家的计算

条件计算

稀疏 MoE 的本质是一种条件计算

条件计算指的是：模型根据输入内容，动态决定执行哪些参数和计算路径

普通稠密模型的计算路径是固定的：

x1→Fx2→Fx3→F\mathbf{x}_1\to F\\ \mathbf{x}_2\to F\\ \mathbf{x}_3\to F\\ x1​→Fx2​→Fx3​→F

所有输入都经过同一个完整网络

而在 MoE 中则有：

x1→{E1,E4}x2→{E2,E3}x3→{E5,E6}\mathbf{x}_1\to \{E_1,E_4\}\\\mathbf{x}_2\to \{E_2,E_3\}\\\mathbf{x}_3\to \{E_5,E_6\}\\ x1​→{E1​,E4​}x2​→{E2​,E3​}x3​→{E5​,E6​}

不同输入可以激活不同专家，因此得到不同的有效计算路径

需要注意的是，整个 MoE 模型的参数集合是固定的，发生变化的只是每个输入实际使用的参数子集

所以 MoE 也可以理解为：

一个大模型中包含多个候选子网络，每个输入只执行其中一部分\text{一个大模型中包含多个候选子网络，每个输入只执行其中一部分} 一个大模型中包含多个候选子网络，每个输入只执行其中一部分

也就是相当于实现了总参数量（正比于专家总数 NNN）和实际计算量（正比于每个输入激活的专家数 kkk）之间的解耦

专家网络

在 MoE 中，专家网络是对输入隐藏表示进行特征变换的独立子网络

第 ttt 个 Token 进入 MoE 层前的隐藏表示为：

xt∈Rd\mathbf{x}_t\in\mathbb{R}^d xt​∈Rd

第 iii 个专家记为：

Ei(⋅;θi)E_i(\cdot;\theta_i) Ei​(⋅;θi​)

其中，θi\theta_iθi​ 表示专家 iii 独立拥有的参数

该专家对当前 Token 所对应隐藏表示的计算结果为：

et,i=Ei(xt),et,i∈Rd\mathbf{e}_{t,i} = E_i(\mathbf{x}_t),\quad \mathbf{e}_{t,i}\in\mathbb{R}^d et,i​=Ei​(xt​),et,i​∈Rd

其中，et,i\mathbf{e}_{t,i}et,i​ 表示专家 iii 对第 ttt 个 Token 输出的隐藏表示

需要特别区分的是，Ei(xt)E_i(\mathbf{x}_t)Ei​(xt​) 仅是第 iii 个专家的输出，并不是整个 MoE 层的最终输出，整个 MoE 层还需要再后续把一个或多个专家的输出进行组合

在本节中，我们仅研究每个 Ei(⋅)E_i(\cdot)Ei​(⋅) 的具体实现，至于如何判断这个专家是否被选择，则是后文讨论的内容

常见专家设置

在现代 Transformer MoE 中，一个专家就是一个独立的前馈网络 FFN\text{FFN}FFN

在普通 Transformer 中，一个 Block 通常包含两个子层：

Attention 子层 + FFN 子层\text{Attention 子层 + FFN 子层} Attention 子层 + FFN 子层

普通稠密 Transformer 对所有 Token 都使用同一个 FFN：

xt→FFN→et\mathbf{x}_t\to\text{FFN}\to\text{e}_t xt​→FFN→et​

MoE 则准备多个参数不同的 FFN：

E1,E2,…,ENE_1,E_2,\dots,E_N E1​,E2​,…,EN​

所以从架构上来讲，经典 Transformer MoE 可以理解成：把原本共享的一个 FFN，扩展成为多个可选择的 FFN

专家内部结构

一个经典的 FFN 专家通常分为三步：

升维线性变换→非线性激活→降维线性变换\text{升维线性变换}\to\text{非线性激活}\to\text{降维线性变换} 升维线性变换→非线性激活→降维线性变换

其中：

其中，dmodeld_{\text{model}}dmodel​ 为 Transformer 对每个 Token 隐藏表示的特征维度，dffd_{\text{ff}}dff​ 为专家层内部的中间维度，ϕ(⋅)\phi(\cdot)ϕ(⋅) 为非线性激活函数

  1. 对输入特征做升维，则专家具有更多中间神经元，可以学习更多不同的非线性响应
  2. 而输出维度必须回到 dmodeld_{\text{model}}dmodel​，则是为了所有专家具有相同的输出维度，从而做后续的加权组合

专家差异产生

虽然不同专家使用相同的结构，但由于它们参数的初始化不完全相同，训练过程接收的输入也可能不同，因而获得的梯度更新也不完全相同

设专家 iii 的参数为 θ\thetaθ，其一次梯度更新为：

其中，η\etaη 为学习率，L\mathcal{L}L 为训练损失

随着训练的进行，每个专家的参数也会逐渐朝着不同方向更新，不同专家会倾向于处理不同的隐藏表示

但是需要注意，专家可能形成不同的功能倾向，但不保证对应明确的人类语义类别，这也是 MLP 内部不可解释性的体现

在 Transformer MoE 中，专家 FFN 对于每个 Token 对应的隐藏表示做独立计算

门控的作用

经典 FFN 仅使用一个激活函数：

ϕ(W1x)\phi(W_1\mathbf{x}) ϕ(W1​x)

此时，中间特征是否保留以及被保留多少主要由激活函数决定

而门控 FFN 则显式计算两条分支：门控分支和内容分支，然后通过元素对位相乘，让每个中间维度的内容都受到门控分支的调制

因此，每个中间特征不仅经过非线性激活，还会被另一个输入相关的信号控制

共享专家

经典 MoE 中，所有专家都是可选择的独立专家：

E1,E2,…,ENE_1,E_2,\dots,E_N E1​,E2​,…,EN​

现代 LLM 架构中，进一步引入共享专家的概念

在这些架构中，专家模型被分为两类：

E1shared,E2shared,…,ENssharedE_{1}^{\text{shared}},E_2^{\text{shared}},\dots,E_{N_s}^{\text{shared}} E1shared​,E2shared​,…,ENs​shared​

以及：

E1routed,E2routed,…,ENrroutedE_1^{\text{routed}},E_2^{\text{routed}},\dots,E_{N_r}^{\text{routed}} E1routed​,E2routed​,…,ENr​routed​

其中，共享专家对输入执行公共特征变换，而路由专家对输入提供差异化特征变换

在专家本身的网络结构层面，二者都可以使用普通的 FFN 或者 SwiGLU FFN，其区别不在于网络结构，而在于使用方式：

  • 共享专家面向所有 Token 使用
  • 路由专家只面向被分配给它的 Token 使用

共享专家设计的动机在于，我们希望公共知识能够被固定专家所承载，从而可以减少所有路由专家重复学习相同特征的开销

细粒度专家

经典 MoE 往往直接复制多个完整的 FFN：

Ei:dmodel→dff→dmodelE_i:d_{\text{model}}\to d_{\text{ff}}\to d_{\text{model}} Ei​:dmodel​→dff​→dmodel​

而细粒度专家的思路则是，把一个较大的专家拆分成多个中间维度更小的专家，类似于单头注意力拆分成多头注意力机制的思路

例如，原专家中间维度为：

可以将其拆分成为 mmm 个较小的专家，每个专家的中间维度为：

多个小专家可以提供更加精细的参数划分，使得模型拥有更加丰富的专家组合方式

需要注意的是，每个细粒度专家仍然是 FFN 结构，只是专家数量变多，每个专家规模变小，但是专家内部所遵循的 “升维 - 激活 - 降维” 的基本逻辑没有改变

Router 为什么使用线性层

我们可能会有疑问：

专家网络很复杂，为什么 Router 往往只需要几个简单的线性层，它能否胜任专家选择的任务？

Router 之所以选择线性层，主要是基于以下的三个考虑：

  1. Router 的任务相对简单：它不负责完成复杂的特征变换，只负责产生 NNN 个专家分数，因此过于复杂的网络结果可能效果并不好
  2. 输入已经是上下文化的隐藏表示：Router 的输入不再是原始的 Token ID，而是经过嵌入、注意力和前面多层 Transformer 吹，包含当前 Token 以及上下文信息的特征表示，因此 Router 不必重新从原始文本中提取复杂特征，只需要在已有隐藏空间中学习专家划分边界
  3. Router 会作用于每个 Token：一个批次中可能包含大量 Token，如果 Router 本身就很复杂，则会引入明显的额外计算

无偏置 Router

很多现代架构中使用：

负载均衡损失

在 MoE 中，Router 会根据每个 Token 的隐藏表示选择某个专家来处理这个 Token：

xt→pt→St\mathbf{x}_t\to\mathbf{p}_t\to\mathcal{S}_t xt​→pt​→St​

如果只使用主任务损失训练，Router 可能会把大量 Token 都分配给少数几个专家，而其他专家几乎不会被使用

所谓的负载均衡损失就是在主任务损失之外增加一种辅助损失，用于约束 Router，不要让所有的 Token 都过度集中在少数几个专家上

最终的总损失通常写成：

Ltotal=Ltask+λbalLbal\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{task}} + \lambda_{\text{bal}}\mathcal{L}_{\text{bal}} Ltotal​=Ltask​+λbal​Lbal​

其中，Ltask\mathcal{L}_{\text{task}}Ltask​ 表示语言建模、分类等主任务的损失，Lbal\mathcal{L}_{\text{bal}}Lbal​ 表示专家负载均衡损失，λbal\lambda_{\text{bal}}λbal​ 表示均衡损失权重

设置负载均衡损失的目的不是为了让专家更好的完成任务，而是调整 Router 的行为，尽可能避免所有 Token 都推给少数几个专家去完成

专家塌缩

假设当前模型中有四个专家：

E1,E2,E3,E4E_1,E_2,E_3,E_4 E1​,E2​,E3​,E4​

训练初期，由于随机初始化，专家 E1E_1E1​ 可能偶然比其他专家表现稍好，Router 因而更倾向于把 Token 分给 E1E_1E1​

于是形成正反馈：由于 E1E_1E1​ 接收更多 Token，因而获得更多梯度，训练更充分，从而表现相对更好，Router 则会进一步偏向于 E1E_1E1​

最终可能导致，分配给 E1E_1E1​ 的 Token 数量远超过其余几个专家，这种现象就称为专家塌缩（Expert collapse），或者路由塌缩（Routing collapse），负载不均衡（Load imbalance）

这会造成热门专家容量溢出，同时冷门专家得不到充分训练，大量专家参数没有得到有效的使用，最繁忙的专家变成计算瓶颈，MoE 的参数扩展优势也无法得到体现

为解决这一问题，需要引入额外的 Lbal\mathcal{L}_{\text{bal}}Lbal​，来约束 Router 的专家使用分布

在 Transformer 的子层中，MoE 通常不改变替换注意力子层，而是替换原来的逐位置前馈网络 FFN 子层
