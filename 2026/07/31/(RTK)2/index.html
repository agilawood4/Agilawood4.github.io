GNSS 系统

GNSS 系统组成

GNSS 是一套完整的空间基础设施，一般分为三个部分：

  • 空间段
  • 地面控制段
  • 用户段

空间段

GNSS 的空间段即在轨运行的导航卫星，每颗卫星主要完成三件事：

  1. 维持自身的高稳定时间基准
  2. 在指定频率上发射导航信号
  3. 广播卫星轨道、钟差、健康状态等导航信息

卫星并不知道某个用户 / 接收机的位置，也不会直接告知这个用户 / 接收机的坐标位置，卫星只是持续广播带有时间和轨道信息的信号，用户接收机根据多个卫星信号自行完成自身位置的解算

地面控制段

地面控制段由监测站、主控站和上行注入设施等组成，它主要负责：

  1. 监测卫星轨道和卫星钟的运行状态，估计轨道参数和钟差参数
  2. 生成导航电文，将更新后的信息上传卫星
  3. 监控卫星的健康状态

GNSS 系统的地面控制段和上一节我们提到的基准站是两个概念：

  1. GNSS 系统地面控制段：维护整个卫星导航系统
  2. RTK 基准站：为流动站提供差分观测信息

用户段

用户段包括：

  1. GNSS 天线
  2. 射频前端
  3. 基带处理芯片
  4. 定位处理器
  5. 上层应用软件

手机、测量型接收机，无人机导航板卡和车载 GNSS 模块都属于用户段设备，只是它们的天线、跟踪能力、频点数量和观测精度有所不同

常见 GNSS 系统

目前在 RTK 定位解算中常用的全球卫星导航系统包括：

  1. GPS：美国
  2. BDS：北斗（中国）
  3. Galileo：欧盟
  4. GLONASS：俄罗斯

此外还有区域系统和增强系统，如 QZSS，NavIC，SBAS

这些系统的基本定位原理相似：都通过导航卫星广播测距信号和导航信息，使用户接收机获得 “卫星 - 接收机” 之间的观测关系

不同系统之间的区别可能在于它们所使用的：

  1. 载波频率
  2. 测距码结构
  3. 导航电文格式
  4. 时间系统
  5. 坐标基准
  6. 卫星轨道类型不
  7. 信号调制方式
  8. 卫星编号方式

可能有所不同

因此，多系统接收机虽然能够同时接收 GPS，BDS，Galileo 等信号，但不能简单地把所有数据完全等同处理，后续还要考虑系统时间偏差、不同频点、不同星历格式和不同的硬件延迟

RTKLIB 在软件层面将不同卫星系统统一映射为内部卫星编号和观测结构，从而为后续定位算法提供相对统一的数据接口

GNSS 卫星信号

GNSS 卫星信号本质上是一种从卫星天线发射到地面的无线电电磁波

载波

载波是具有较高频率的周期性电磁波，理想情况下，可以用正弦信号表示：

c(t)=Acos⁡(2πfct+φ0)c(t) = A\cos(2\pi f_ct + \varphi_0) c(t)=Acos(2πfc​t+φ0​)

其中，AAA 为载波振幅，fcf_cfc​ 为载波频率，ttt 为时间，φ0\varphi_0φ0​ 为初始相位

之所以称之为 “载波”，是因为它负责承载测距码和导航数据，使得这些信息能够通过无线电从卫星传播到接收机

需要注意的是，载波本身无法直接体现卫星到接收机的几何距离，它只是一种实际传播的电磁波；载波相位观测值是接收机对该电磁波相位进行跟踪后生成的测量结果

频率与波长

载波频率 fcf_cfc​ 和波长 λ\lambdaλ 之间满足：

λ=cfc\lambda = \frac{c}{f_c} λ=fc​c​

其中，ccc 为真空中的光速

载波频率越高，对应的波长越短，例如 GPS L1 载波频率为 1575.42MHz，其波长约为 19cm，这意味着卫星与接收机之间的距离每改变一个完整 L1 波长，载波相位就变化一整周

GPS 民用信号分布在 L1、L2、L5 等频段，Galileo 使用 E1、E5a、E5b、E5、E6 等频段，北斗则使用 B1I，B1C，B2a，B2b，B3I 等频段

需要区分 “L1” 和 “L1 C/A” 的概念，以 GPS 为例：

  1. L1 主要表示一个载波频段
  2. C/A 表示一种测距码
  3. L1 C/A 表示在 L1 频段上传输的 C/A 码民用信号

同一个频率上可以存在多个不同的信号分量，同一种导航系统也可以在不同频率上传输信号

载波信息

如果每颗卫星只是单纯发送一段正弦载波，接收机会遇到三个问题：

  1. 无法区分收到的是哪个卫星的信息
  2. 难以测量信号的传播时间
  3. 无法获得该卫星的轨道和钟差信息

因此，卫星在载波上附加了测距码和导航数据等信息

目前阶段，我们可以把一颗卫星的导航信号简化建模成：

s(t)=AC(t)D(t)cos⁡(2πfct+φ0)s(t) = A C(t)D(t)\cos(2\pi f_ct + \varphi_0) s(t)=AC(t)D(t)cos(2πfc​t+φ0​)

其中，s(t)s(t)s(t) 表示卫星发射的完整导航信号，AAA 表示信号幅度，C(t)C(t)C(t) 表示测距码，D(t)D(t)D(t) 表示导航数据，fcf_cfc​ 表示载波频率，φ0\varphi_0φ0​ 表示初始载波相位

需要注意的是，这只是便于理解载波所携带信息而构建的概念模型，现代 GNSS 信号可能包含数据通道、导频通道、主次码以及更复杂的调制方式，不能用上述公式简单的表示

目前我们只需要理解 “完整导航信号 = 载波 + 测距码 + 导航信息” 这一核心关系即可

测距码

测距码是由 +1 和 -1，或者等价的二进制 0 和 1 构成的高速序列，通常被称为 PRN code，ranging code，spreading code

其中，PRN（Pseduo-Random Noise）被称为伪随机噪声码，所谓的 “伪随机” 指的是：PRN 看起来是随机序列，实际上由确定的规则生成，接收机能够完全生成相同的本地副本

测距码中的每一个基本单元称为码片（clip），一个码片可能包含多个数据比特，因此码片速率通常远高于导航的数据比特率

  • 码片（clip）：测距码序列的基本单位
  • 数据比特（bit）：导航电文的基本单位

测距码的作用

（1）识别卫星

不同卫星通常被分配不同的测距码序列，接收机如果想搜索某颗卫星，就在内部生成该卫星对应的 PRN 码，然后与接收到的信号进行相关运算

如果本地码与接收信号中的码序列对齐，相关值会明显增大

因此，接收机通过本地 PRN 码与接收信号之间的相关特性识别卫星

（2）测量传播时间

假设卫星在发射时使用的测距码为：

C(t)C(t) C(t)

信号经过传播后，接收机收到的是延迟版本：

C(t−τ)C(t - \tau) C(t−τ)

其中，τ\tauτ 表示信号从卫星传播到接收机所经历的时间

接收机不断调整本地码的时间位置，当本地码与接收码对齐时，可以估计传播延迟：

τ^\hat{\tau} τ^

再通过：

距离≈cτ^\text{距离} \approx c\hat{\tau} 距离≈cτ^

即可得到卫星接收机的测距信息

实际情况中，由于卫星钟，接收机钟，大气传播和硬件延迟等影响，该测量结果不是真实集合距离，而是我们后需要讲的伪距

导航电文

导航电文是卫星广播的低速数字信息，它通常包含定位所需要的参数，例如：

  1. 卫星轨道参数，即广播星历
  2. 卫星钟差改正参数
  3. 卫星健康状态
  4. 时间系统信息
  5. 星座概况或历书
  6. 电离层模型参数
  7. 信号群延迟或码偏差参数

接收机获得导航电文后，才能计算卫星在某一时刻的位置，以及卫星钟相对于系统时间的偏差

在本节，需要区分以下三个概念：

  1. 载波：承载测距码和导航电文，并提供高精度相位测量基础
  2. 测距码：主要用于卫星识别和传播时间测量
  3. 导航电文：提供卫星轨道、时间、钟差等信息

GNSS 多频段

以 GPS 为例，其民用信号包括 L1、L2、L5 等多个频段，其它系统也具有多个频段和型号，多频段设计主要有以下作用

  1. 估计或消除电离层影响

电离层延迟与信号频率有关，接收机同时捕获两个或多个频率的观测值后，可以利用不同频率上的电离层效应差异，构造电离层改正或组合观测值

  1. 提高可用性和可靠性

如果某个频率的信号受到遮挡、干扰、多路径影响或接收机跟踪失败，其他频率仍然可以提供有效观测，此时多频观测相当于提供了一定程度的冗余

  1. 有利于模糊度固定

不同频率的载波具有不同波长，而把不同频率的载波相位进行组合，可以形成宽巷、窄巷等组合

部分组合具有更长的等效波长，更有利于快速确定整周模糊度

GNSS 接收机

接收机并非收到信号后就可以直接计算得到坐标，而是必须经历一条完整的信号处理链：

天线→射频前端→模数转换→捕获→跟踪→导航电文解调→观测量生成\text{天线}\to\text{射频前端}\to\text{模数转换}\to\text{捕获}\to\text{跟踪}\to\text{导航电文解调}\to\text{观测量生成} 天线→射频前端→模数转换→捕获→跟踪→导航电文解调→观测量生成

天线

GNSS 天线负责接收来自不同方向的卫星电磁波，并将其转换为射频电信号

天线性能会直接影响：

  • 接收信号强度
  • 多路径抑制能力
  • 相位中心稳定性
  • 不同高度角卫星的增益
  • 载波相位测量稳定性

测量型 RTK 天线与普通手机内置天线存在显著差异，前者通常更重视：

  • 相位中心稳定性
  • 多频接收
  • 低高度角信号性能
  • 多路径抑制

天线本身不输出坐标，也不直接输出伪距，只负责接收电磁信号

射频前端

射频前端通常执行：

  • 低噪声放大
  • 频带滤波
  • 自动增益控制
  • 下变频
  • 中频或基带输出

卫星信号到达地面时非常微弱，不能直接交给普通数字处理器处理，因此需要先放大和滤波

AGC（Automatic Gain Control）即自动增益控制，它根据输入信号整体功率调整前端增益，使输出信号保持在适合模数转换器处理的范围内

模数转换

经过射频处理后的模拟信号，需要经过 ADC（Analog-to-Digital Converter），即模数转换器，转变为离散数字采样值

之后的捕获、跟踪和相关处理通常在数字基带中完成，此时得到的仍是采样信号，不是伪距和载波相位观测值

卫星捕获

卫星捕获是接收机首次发现并粗略识别某颗卫星信号的过程

接收机事先并不知道两个关键参数：

  1. 接收测距码相对于本地码延迟了多少
  2. 接收载波由于卫星与接收机相对运动等原因产生了多少频率偏移

因此，捕获本质上是测距码和接收载波的二维搜索

  • 码相位：测距码在一个码周期中的时间位置
  • 载波频率偏移：接收载波与标称频率之间的差值，主要包括多普勒频移和接收机振荡器偏差

接收机为某颗卫星生成本地 PRN 码，并尝试不同的本地码延迟和载波频率，然后计算相关值，当某个码相位和频率组合产生显著的相关峰时，就表明接收机发现了对应的卫星及其粗略码延迟和粗略载波相位偏移

卫星捕获阶段的输出只是信号的粗略同步参数，还不能直接用于高精度 RTK

信号跟踪

捕获成功后，卫星和接收机仍在运动，接收机本地时钟也在变化，因此码相位和载波相位会不断改变

跟踪模块的任务是连续调整本地复制信号，使其始终与接收信号保持同步

常见跟踪环包括：

  • DLL
  • FLL
  • PLL

DLL：码跟踪环

DLL（Delay-Locked Loop），即延迟锁定环，它主要跟踪测距码的时间延迟

接收机通常构造三路本地码：

  • Early：超前码
  • Prompt：即时码
  • Late：滞后码

记三路相关输出为：

E,P,LE,\quad P,\quad L E,P,L

如果本地与接收码准确对齐，那么 Early 和 Late 两侧通常相对平衡

DLL 根据二者差异构造鉴别量，例如概念上：

eDLL∝∣E∣−∣L∣e_{\text{DLL}} \propto |E|-|L| eDLL​∝∣E∣−∣L∣

然后调整本地码发生器：

  • 若 Early 更大，说明本地码位置偏向一侧
  • 若 Late 更大，说明本地码位置偏向另一侧
  • 当二者接近平衡时，Prompt 位于相关峰附近

DLL 最终持续输出精确的码相位估计，它是形成伪距观测的重要基础

FLL：频率跟踪环

FLL（Frequency-Locked Loop），即频率锁定环，它主要跟踪载波频率变化

FLL 对较大的频率偏差和较高动态通常比较稳健，因此经常用于：

  • 捕获后的初始载波牵引
  • 高动态条件
  • 辅助 PLL
  • 信号重新捕获

FLL 主要关心载波频率是否一致，而不是非常精确的载波相位

PLL：载波相位跟踪环

PLL（Phase-Locked Loop），即锁相环，它调整本地载波的相位和频率，使本地载波与接收载波保持相位同步

假设接收载波相位为：

φr(t)\varphi_r(t) φr​(t)

本地复制载波相位为：

φl(t)\varphi_l(t) φl​(t)

PLL 通过相关器估计二者的相位差：

Δφ(t)=φr(t)−φl(t)\Delta\varphi(t) = \varphi_r(t) - \varphi_l(t) Δφ(t)=φr​(t)−φl​(t)

然后不断调整本地振荡器，使得：

Δφ(t)→0\Delta \varphi(t)\to 0 Δφ(t)→0

PLL 的连续相位累积结果，是生成高精度载波相位观测值的基础

因此：

  • DLL 主要跟踪码延迟
  • FLL 主要跟踪载波频率
  • PLL 主要跟踪载波相位

相关器

捕获和跟踪都离不开相关运算

假设接收信号为 r(t)r(t)r(t)，接收机生成的本地复制信号为 l(t)l(t)l(t)，在一个积分时间 TTT 内，相关结果在概念上可以表示为：

因此，相关器相当于一个 “匹配检测器”，用来判断本地复制信号与接收信号的相似程度

GNSS 接收机能够在多个卫星信号重叠到达天线的情况下分离它们，关键原因之一就是不同卫星使用了具有良好相关特性（自相关尖锐，互相关接近于零）的测距码

导航电文解调

当接收机已经稳定跟踪载波和测距码后，可以进一步恢复导航数据比特

基本过程是：

去载波→去扩频码→数据比特判决→帧同步→电文校验→参数解析\text{去载波} \rightarrow \text{去扩频码} \rightarrow \text{数据比特判决} \rightarrow \text{帧同步} \rightarrow \text{电文校验} \rightarrow \text{参数解析} 去载波→去扩频码→数据比特判决→帧同步→电文校验→参数解析

接收机需要找到导航电文的：

  • 比特边界
  • 字或页面边界
  • 子帧或帧边界

随后解析出：

  • 广播星历
  • 卫星钟差参数
  • 卫星健康信息
  • 时间参数

接收机输出

完成捕获、跟踪和电文处理后，接收机可以形成后续定位需要的数据

  • 伪距观测值(PPP)

来自于测距码延迟估计，其本质是接收信号码相位与接收机本地时间基准之间的关系，并不是卫星直接发送的距离值

  • 载波相位观测值（LLL）

来自于 PLL 连续载波相位跟踪，接收机可以非常精确的测量出载波的小数相位和历元间相位变化，但初始完整周期数未知，因此后续才会出现整周模糊度

  • 多普勒观测值（DDD）

来自于接收载波频率变化，它与卫星和接收机之间的相对径向速度，以及接收机钟漂等因素有关

  • C/N0

来自于接收机对相关输出中信号功率与噪声水平的估计，C/N0 用来表征某颗卫星中某个信号分量的跟踪质量

  • 导航数据

包括星历、钟差参数、卫星健康状态、时间信息以及其他系统参数

接收机最终输出的信息可以概括为：

信号跟踪结果→P, L, D, C/N0导航电文解析→星历、钟差、健康状态等\text{信号跟踪结果}\to\text{P, L, D, C/N0}\\ \text{导航电文解析}\to\text{星历、钟差、健康状态等} 信号跟踪结果→P, L, D, C/N0导航电文解析→星历、钟差、健康状态等

本节主要是打通卫星发送的原始信号和接收机测出信号之间的关系：

卫星实际广播 接收机生成或解析
载波电磁波 载波相位观测值
测距码 码相位和伪距观测值
导航数据比特 星历、钟差、健康状态
具有一定功率的射频信号 C/N0 估计
频率稳定的载波 多普勒观测值

二者并不完全等价，卫星发射经过调制的原始导航信号，接收机通过捕获、跟踪、相关和电文解调，才能生成伪距、载波相位、多普勒和 C/N0 等观测数据
