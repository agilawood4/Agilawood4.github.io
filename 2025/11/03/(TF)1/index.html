局部前向与梯度计算

在前向传播阶段，每张 GPU 都根据自己的 Local Batch 做独立计算

接着计算梯度：

每张 GPU 都会计算自己模型参数的梯度，比如对于参数 θ\thetaθ 则有：

g0=∇θL0g1=∇θL1g2=∇θL2g3=∇θL3g_0 = \nabla_\theta L_0\\ g_1 = \nabla_\theta L_1\\ g_2 = \nabla_\theta L_2\\ g_3 = \nabla_\theta L_3 g0​=∇θ​L0​g1​=∇θ​L1​g2​=∇θ​L2​g3​=∇θ​L3​

因为不同 GPU 分到的数据不同，即便是同一组参数，也会计算得到不同的梯度：

g1,g2,g3,g4g_1,g_2,g_3,g_4 g1​,g2​,g3​,g4​

如果各自做更新，则原本由同一个模型复制而来的四个模型，会逐渐被训练成四个不同的模型

因此 DDP 要做的一个核心操作就是：梯度同步（Gradient Synchronization）

梯度同步与参数更新

DDP 在 Backword 过程中会对各个 Rank 的梯度做同步，最终的梯度为：

g=g0+g1+⋯gK−1Kg = \frac{g_0 + g_1 + \cdots g_{K-1}}{K} g=Kg0​+g1​+⋯gK−1​​

其中，K=\text{world_size}

同步完成后，各卡上用于反向传播的就是同一个梯度 ggg

而在代码层面，不需要我们手动完成梯度同步，还是只写 loss.backward() 即可，DDP Wrapper 会在 Backward 过程中自动完成梯度的同步

全局梯度

下面我们简单证明，为什么对各卡的梯度做平均，就可以近似代表整个大 Batch 的梯度

假设有 KKK 张 GPU，每张 GPU 上有 BBB 个样本

第 kkk 张 GPU 的平均 Loss 为：

Lk=1B∑i=1Bℓk,iL_k = \frac{1}{B}\sum_{i=1}^B \ell_{k,i} Lk​=B1​i=1∑B​ℓk,i​

整个系统的样本总数为 KBKBKB，如果把全部样本视为一个 Global Batch：

Lglobal=1KB∑k=1K∑i=1Bℓk,iL_{\text{global}} = \frac{1}{KB}\sum_{k=1}^K\sum_{i=1}^B \ell_{k,i} Lglobal​=KB1​k=1∑K​i=1∑B​ℓk,i​

可以写成：

Lglobal=1K∑k=1KLkL_{\text{global}} = \frac{1}{K}\sum_{k=1}^K L_k Lglobal​=K1​k=1∑K​Lk​

对于参数 θ\thetaθ 求梯度：

∇θLglobal=1K∑k=1K∇θLk\nabla_\theta L_{\text{global}} = \frac{1}{K}\sum_{k=1}^K \nabla_\theta L_k ∇θ​Lglobal​=K1​k=1∑K​∇θ​Lk​

而：

gk=∇θLkg_k = \nabla_\theta L_k gk​=∇θ​Lk​

因此则有：

∇θLglobal=1K∑k=1Kgk\nabla_\theta L_{\text{global}} = \frac{1}{K}\sum_{k=1}^K g_k ∇θ​Lglobal​=K1​k=1∑K​gk​

也就是 DDP 后的梯度

因此在标准条件下，多 GPU 分别计算 Local Batch，再平均 Gradient，就等价于对合起来的 Global Batch 计算梯度

参数更新

梯度同步后，每张 GPU 都拥有相同的梯度 ggg，然后所有 Rank 都用该梯度做反向传播：

假设用最简单的梯度下降：

θ′=θ−ηg\theta^{'}= \theta - \eta g θ′=θ−ηg

因为所有 Rank 原始参数相同，同步后的梯度也相同，Optimizer 和学习率也相同，因此：

θ0′=θ1′=θ2′=θ3′\theta_0^{'} = \theta_1^{'} = \theta_2^{'} = \theta_3^{'} θ0′​=θ1′​=θ2′​=θ3′​

模型会继续保持一致

注意：不是只有 Rank 0 上的模型才执行 optimizer.step()，每个 Rank 都要执行

Batch 概念对比

多 GPU 训练有 3 个不同的 Batch 概念需要理解

Local Batch

Local Batch 也称为 Per-GPU Batch Size，它表示每张 GPU 上的 Batch 大小，也就是每张 GPU 依次可以处理几个 Samples

Global Batch

如果 Per-GPU Batch 大小为 8，World Size 为 4，则 Global Batch 大小为 32，整体满足公式：

B_{\text{global}} = B_{\text{per GPU}} \times \text{world_size}

Efficient Batch

如果同时开启了梯度累计，那么则有：

B_{\text{efficient}} = B_{\text{per device}}\times \text{world_size}\times\text{accumulation_steps}

主进程控制

所有 Rank 都会运行同一份 Python 代码，因此如果我们直接 torch.save(...) 则相当于每个 Rank 都会保存一次模型

因此，我们需要通过 rank 号区分，只让 Rank 0 作为主进程，用于完成模型保存等任务
