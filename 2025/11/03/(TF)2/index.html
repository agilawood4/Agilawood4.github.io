Accelerate 分布式训练

上一章我们手写实现了 DDP（分布式数据并行），本章我们介绍 HuggingFace 的 Accelerate，它并不是一套新的算法，而是对 Pytorch 单卡、多 GPU、混合精度、梯度累积等训练工程逻辑的一层统一封装

当前 Accelerate 的 Accelerator 可以统一处理设备放置、分布式模型包装、DataLoader 分片、Optimizer/Scheduler 包装、Mixed Precision 和 Gradient Accumulation 等，很多分布式的细节都不再需要我们手动管理了

Accumulate 原理

假设我们设置 gradient_accumulation_steps=4，即每经过 4 个 Macro Batch 统一更新一次参数：

Accelerate 会自动完成：

  1. 损失缩放（Loss Scaling）
  2. 梯度积累（Gradient Accumulation）
  3. 分布式梯度同步（Distributed Gradient Synchronization）
  4. 优化器同步更新参数（Optimizer Step Time）

所以我们不再需要和 DDP 一样，自己完成多张 GPU 上 Loss 的合并，Accelerate 都会帮我们自动做好

DDP 通信优化

如果梯度累积四次，DDP 需要每次都同步 Gradient，但实际上，前三次对梯度的累积其实不需要同步，只有最后一次做统一的同步即可

而 with accelerator.accumulate(model): ... 会自动负责相应的同步管理，在分布式训练中可以帮我们跳过不必要的梯度同步

首先需要安装对应的包：

每个程序在第一次通过 accelerate 运行时通常要先执行：

它会在终端询问：

终端问题 问题含义 常见选项
Which compute environment are you using? 使用什么硬件/平台训练 LOCAL_MACHINE（本机/服务器，最常用） AWS_SAGEMAKER（AWS SageMaker） AWS_EC2（AWS EC2 裸机） TPU（Google TPU）
Which distributed type would you like to use? 使用哪种多卡并行方式 NO（单卡，不并行） MULTI_GPU（PyTorch DDP，最常用） FSDP（PyTorch 完全分片数据并行，模型太大时选） DEEPSPEED（Microsoft DeepSpeed，超大模型） MEGATRON_LM（NVIDIA Megatron，超大 LLM）
How many machines will you use? 有几台机器参与训练 1（单机，99% 的情况） 2 / 4 / …（多机集群）
How many processes in total will you use? 总共启动多少个 GPU 进程 单机 1 卡 → 1 单机 4 卡 → 4 2 机×4 卡 → 8 通常 = 可见 GPU 总数
What GPU(s) would you like to use? 指定用哪几张 GPU all（用所有可见 GPU，最常用） 0,1（只用到第 0、1 号卡） 0,2,3（跳过某张卡）
What machine rank would you like to use? 这台机器在多机里排第几 0（单机 / 主节点） 1（第二台机器） 2（第三台…）
What is the main process IP address? 主节点（rank 0）的内网 IP 是多少 单机 → 直接回车（null） 多机 → 填主节点 IP，如 192.168.1.10
What is the main process port? 进程间通信用哪个端口 单机 → 直接回车（默认 29500） 多机 → 确保端口未被占用，可改 29501 等
What rendezvous backend would you like to use? 多进程之间用什么机制协调启动 static（固定进程数，手动启动，最常用） c10d（PyTorch 内置） file（共享文件系统）
Are all machines on the same local network? 所有机器在同一个局域网内吗 yes（同一内网，最常用） no（跨网络，需要额外网络配置）
Do you want to use mixed precision? 要不要开启混合精度训练？用什么格式 no（全 fp32，调试用） fp16（float16，老卡 V100 等） bf16（bfloat16，A100/H100/RTX30+ 强烈推荐）
Do you want to use the CPU only? 是否只用 CPU 训练（没有 GPU） no（有 GPU，99% 的情况） yes（纯 CPU 调试）
Do you wish to optimize for TPU training? 是否针对 TPU 做优化 no（不用 TPU） yes（用 TPU 时）
DeepSpeed configuration file path? DeepSpeed 的 JSON 配置文件路径 没选 DeepSpeed → 直接回车跳过 选了 → 填路径如 ds_zero2.json
FSDP configuration? FSDP 的分片/Offload 等配置 没选 FSDP → 回车跳过 选了 → 交互式追问分片策略、CPU offload 等
What type of FSDP sharding strategy? FSDP 参数分片策略 FULL_SHARD（ZeRO-3 级别，最省显存） SHARD_GRAD_OP（ZeRO-2 级别） NO_SHARD（DDP 级别）
Do you want to offload parameters to CPU? 是否把部分参数卸载到 CPU 内存 no（不 offload，速度快） yes（显存不够时，用内存换显存）
Do you want to use Dynamo? 是否启用 TorchDynamo 编译优化 no（默认，稳定） yes（PyTorch 2.x 实验性加速）
